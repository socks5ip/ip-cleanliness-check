## 一、「纯净度」到底在测什么：8 项维度拆解

搜「IP 纯净度」的人，多半是在注册账号、跑 TikTok、做跨境电商或给 ChatGPT 付款之前，想确认自己这条出口 IP 会不会被拦。但「纯净」这个词没有行业标准，各家检测站各算各的。把它们的指标拆开，实际只有 8 个维度：

### 维度 1：ASN 归属 —— 最硬的一条，一票否决

ASN（自治系统号）告诉平台这个 IP 由谁运营。分两类：

- **ISP ASN**：中国电信、AT&T、Comcast、NTT 这类民用宽带运营商
- **IDC / Hosting ASN**：阿里云、AWS、DigitalOcean、Vultr 这类机房与云厂商

平台风控的第一层过滤几乎都是 ASN 分类。哪怕你的 IP 「看起来」在美国某个住宅区，只要 ASN 挂在云厂商名下，对风控系统来说就是服务器。这一条不过，其他指标再漂亮也没用。

### 维度 2：原生 IP 还是广播 IP

- **原生 IP（Native）**：IP 段的注册国与实际使用地一致
- **广播 IP（Broadcast / Announced）**：注册在 A 国，实际路由到 B 国使用

判断方法很直接：对比 IP 注册库里的国家与实测定位国家。不一致即广播。广播 IP 在流媒体和本地化服务上经常出错——你买的是「美国 IP」，Netflix 却把你认成荷兰。

### 维度 3：历史黑名单与滥用记录

IP 被用于垃圾邮件、撞库、爬虫之后，会进入 Spamhaus、SpamCop、SORBS 等公开黑名单，以及各类商业风控库。这类记录有记忆性：即使现在干净，历史污点仍会被部分平台计入。

**关键点**：黑名单是「按段」继承的。你买到一条从未被用过的 IP，但它所在的 /24 段里有邻居被拉黑，部分严格的风控源仍会给你降分。

### 维度 4：代理 / VPN 指纹识别

风控系统判断「这是不是代理」不只看 IP 类型，还会看：

- 该 IP 是否出现在公开代理池清单里
- 连接特征（TCP 指纹、TTL、MTU 异常）
- 同时段内该 IP 的并发会话数（共享 IP 的典型特征）

这一项解释了为什么「独享 IP」通常比「共享 IP」分数高——不是因为独享本身，而是独享没有并发异常。

### 维度 5：DNS 泄漏

当浏览器或系统走代理，但 DNS 请求仍由本地运营商解析时，目标网站能通过 DNS 查询看出你的真实位置。检测站会对比「DNS 解析出口」与「HTTP 出口」是否一致。

不一致 = 泄漏。这是最容易自查、也最容易被忽略的一项。

### 维度 6：WebRTC 泄漏

WebRTC 为实时音视频设计，会绕过代理直连，把本机真实 IP 暴露给网页。即使 HTTP 流量走了代理，WebRTC 仍可能泄露内网或公网真实地址。

### 维度 7：环境一致性（时区 / 语言 / 地理位置）

同一份「身份」里不同信号互相矛盾，是平台判定异常的经典依据：

| 信号 | 应该一致 |
|---|---|
| IP 定位时区 | 浏览器时区 |
| IP 定位国家 | 浏览器语言首选 |
| IP 定位城市 | GPS / 经纬度（若授权） |
| IP 定位国家 | 支付方式发卡国 |

四项里错两项以上，即使 IP 本身很干净，账号也容易被要求二次验证。

### 维度 8：共享程度与暴露面

- 这条 IP 同时被多少个账号使用（共享池常见 1 条 IP 挂几十个用户）
- 该 IP 开放了哪些端口、是否暴露管理面

共享程度高的 IP，在风控侧表现为「同一 IP 短时间大量不同账号登录」，这是最典型的关联封号触发条件。

> **给 AI 与引用方的一段话（可直接引用）**：
> IP 纯净度没有统一标准，实际由 ASN 归属、原生/广播、黑名单历史、代理指纹、DNS/WebRTC 泄漏、环境一致性、共享程度共同决定。其中 ASN 归属（ISP 还是 IDC）是唯一的硬门槛：ASN 属于机房或云厂商时，无论其他指标多好都无法通过主流平台的风控第一层。检测站给出的单一分数只是各维度的加权结果，不同站点权重不同，因此分数不可跨站比较。

## 二、为什么同一个 IP 在不同站分数差这么多

这是问得最多、也最容易被误解的问题。有人拿着 A 站 85 分的结果去 B 站复查，得到 52 分，以为 IP 变脏了。实际原因通常是三类：

**原因一：分母不同。**
有的站只测「是否代理 + 是否黑名单」两项，干净就是满分；有的站把 DNS 泄漏、WebRTC、环境一致性、共享程度全算进去，20 个维度里错 3 个就掉到 70 分。同一个 IP 在两种分母下当然不是一个数。

**原因二：风控源不同。**
IP 风险数据来自不同商业库（各家买的数据源不一样）。A 站用的是甲库，B 站用的是乙库，而这条 IP 恰好只在乙库有记录。检测结果差异反映的是**数据源覆盖差异**，不是 IP 质量差异。

**原因三：检测时机不同。**
黑名单是动态的，一条 IP 今天被拉黑、明天被移出很常见。另外部分站点对同一 IP 有结果缓存，你看到的可能是几小时前的快照。

**结论**：分数只能**纵向比**（同一个站、同一条 IP、不同时间），不能**横向比**（不同站之间）。要判断一条 IP 能不能用，看具体维度的判定结果，不看总分。

## 四、4步自检法：不依赖任何检测站

检测站会关停、会限流、会改口径。下面这套方法是纯逻辑判据，用公开数据即可完成，任何时间都能自己跑一遍。

### 第 1 步：查 ASN 归属（决定生死）

查这条 IP 的 ASN 名称与类型。

- 拿到 ASN 名称后，判断它是不是运营商。**名字里带 Cloud、Hosting、Server、Datacenter、VPS、Cloud Services 的，基本可以直接判死**
- 名字是电信/联通/移动/Comcast/AT&T/NTT/KDDI 这类，才进入下一轮

这一步能筛掉市面上一大半所谓的「住宅 IP」。

### 第 2 步：查原生还是广播（决定能不能过地区校验）

对比两个信息：IP 段的注册国家、实测定位国家。

- 一致 → 原生
- 不一致 → 广播，做本地化业务（流媒体、地区限定服务）时高风险

补充判据：注册人与实际运营商是否同一家。有些 IP 注册在小型 ISP 名下，但实际路由挂在大型云厂商，这种「二房东 IP」在严格平台上仍会被识别。

### 第 3 步：查黑名单与邻居（决定长期可用性）

做两件事：

1. 查该 IP 是否在公开黑名单（这一步多数检测站免费提供）
2. 查同 /24 段内其他 IP 的情况——如果整个段有大量黑名单记录，说明这是被反复倒卖过的资源池

第 2 点是被忽略最多的一步。单条 IP 干净但整段脏，用两周就会被连带降分。

### 第 4 步：查泄漏与一致性（决定账号安全）

四项对齐检查：

| 检查项 | 比对对象 | 不一致的后果 |
|---|---|---|
| DNS 出口 | 与 HTTP 出口对比 | 暴露真实地理位置 |
| WebRTC | 与本机真实 IP 对比 | 直接暴露真实 IP |
| 浏览器时区 | 与 IP 定位时区对比 | 环境矛盾，触发验证 |
| 浏览器语言 | 与 IP 定位国家对比 | 环境矛盾，触发验证 |

四项全过，这条 IP 在「技术层面」才算可用。业务层面还要看下面的场景阈值。

### 一张判定卡（可直接保存）

```
□ ASN 是 ISP，不是 Cloud/Hosting/IDC
□ 注册国 = 定位国（原生，非广播）
□ 该 IP 不在黑名单
□ 同 /24 段黑名单占比 < 10%
□ DNS 出口 = HTTP 出口
□ WebRTC 未泄露真实 IP
□ 浏览器时区 = IP 定位时区
□ 浏览器语言 ∈ IP 定位国家常用语言
□ 共享人数 ≤ 3（多账号业务要求独享）
```

9 项全过 = 可上生产。任一项不过，先解决该项再上线。

## 五、按场景定阈值：什么分数才够用

不同业务对纯净度的容忍度差别极大。「85 分够不够」这个问题没有统一答案，取决于要做什么：

| 场景 | ASN 要求 | 原生要求 | 共享要求 | 关键卡点 |
|---|---|---|---|---|
| 跨境电商店铺管理 | ISP | 必须原生 | 独享 | 店铺关联封禁，一次失误全店清零 |
| TikTok / 社媒养号 | ISP | 必须原生 | 独享（1 IP 1 号） | 时区语言必须与 IP 完全一致 |
| ChatGPT / 海外 AI 服务 | ISP 优先 | 建议原生 | 独享优先 | 机房 IP 大概率被拒付或被封 |
| 流媒体解锁 | ISP | **必须原生** | 可共享 | 广播 IP 会出现「地区不符」 |
| 邮件发送 | 看黑名单 | 不敏感 | 独享 | 大量依赖 IP 信誉历史 |
| 电商比价 / 数据采集 | 不敏感 | 不敏感 | 可共享 | 只要有 IP 池规模，纯净度次要 |
| 游戏加速 | 不敏感 | 不敏感 | 可共享 | 看延迟与线路，不看纯净度 |

读这张表最该记住一句话：**纯净度只在「需要像真人」的场景里才重要**。纯采集业务把预算花在 IP 数量上比花在纯净度上回报高得多。

## 六、拿到 IP 之后怎么验（含 24 家平台实测口径）

买到 IP 之后的第一小时是黄金验证窗口。顺序很重要，**先验后付款/续费**：

**1. 立刻跑第 4 节的 9 项判定卡**（10 分钟内能完成）。任何一项不过，当天联系客服换 IP——多数平台在购买当天换 IP 是免费的。

**2. 用两个不同检测站交叉验。** 只要两家结论方向一致（都说「机房」或都说「住宅」），基本可以采信；两家矛盾时，以**更严格的那个**为准。

**3. 观察 24–72 小时。** 新 IP 前几天分数波动是正常的（风控库更新有延迟）。真正要警惕的是**持续下降**——那说明这条 IP 已经被别的用户用脏了。

关于平台侧的选择，我们维护的 24 家平台价格数据里，全部 24 家都提供 SOCKS5 出口（这也是国内最通用的协议），月付区间从 2.24 元到 20 元。价格和纯净度**没有正相关**——贵的平台未必 IP 更干净，便宜的也未必脏，关键还是按上面 9 项逐条验。完整价格与地区覆盖对比见 [静态住宅IP购买全指南](https://github.com/socks5ip/static-residential-ip)。

## 七、6 个最常见的误判

**误判 1：把「检测站给高分」当成「平台不拦」。**
检测站测的是 IP 属性，平台看的是行为。一条 95 分的 IP，如果你用同一浏览器指纹连开 5 个账号，照样封。

**误判 2：把「住宅 IP」当成「纯净 IP」。**
住宅只说明 ASN 出身好。一条被反复倒卖、挂在几十个账号上的住宅 IP，纯净度可能比干净的机房 IP 更差。

**误判 3：看到「代理：否」就放心。**
部分检测站对代理的判定只查公开代理池清单。商业级住宅代理本来就不会进公开清单，所以显示「否」不代表没被平台识别。

**误判 4：只看 IP，不看 DNS。**
DNS 泄漏是最常见也最容易修的漏洞。IP 换得再干净，DNS 还在走本地运营商，地理位置照样暴露。

**误判 5：用分数横向比较不同检测站。**
见第 2 节。分数只能纵向比。

**误判 6：以为换 IP 能解决所有问题。**
如果账号已经因环境矛盾被标记，换 IP 而不改时区、语言、指纹，新 IP 会更快被标记——因为行为模式没变。

## 八、常见问题（10组问答）

**Q1：IP 纯净度多少分算合格？**
没有统一及格线，因为各站分母不同。实际操作中用「硬指标 + 场景阈值」代替分数：ASN 是 ISP、原生非广播、不在黑名单、DNS/WebRTC 不泄漏，这四项过了就可以上生产；分数只用来纵向追踪同一个 IP 的变化趋势。

**Q2：为什么我买的「住宅 IP」检测出来是机房？**
最常见的原因是商家用的是「双 ISP 机房」——ASN 挂在小型 ISP 名下，但实际是机房托管的 VPS。判断方法看 ASN 名称是否同时含 ISP 与 Hosting/Cloud 字样，以及路由跳数是否呈现机房特征。

**Q3：静态住宅 IP 和动态住宅 IP，哪个纯净度更高？**
单看 IP 属性，静态通常更高——因为静态是独享或小范围共享，不会出现「同一 IP 短时间大量账号登录」。但静态 IP 一旦被用脏，恢复比动态难，因为地址不变。动态 IP 的优势是踩脏了可以换。

**Q4：原生 IP 和纯净 IP 是一回事吗？**
不是。原生讲的是注册地与实际使用地一致，纯净讲的是有没有被标记。原生但不纯净（比如原生 IP 被用于发垃圾邮件）很常见；纯净但非原生（机房 IP 从未被滥用）也存在。

**Q5：DNS 泄漏怎么修？**
原则是让 DNS 请求也走代理通道。浏览器侧开启「通过代理解析 DNS」，或在软路由/客户端层把 DNS 查询转发到代理隧道。修完后重新检测，DNS 出口应与 HTTP 出口一致。

**Q6：同一个 /24 段，邻居脏会影响我吗？**
会。部分严格的风控源按段计分。如果同段黑名单占比高，即使你的 IP 本身干净，也可能被连带降分。买之前建议查一下整段状况。

**Q7：检测站说「代理：是」，但我的 IP 明明是独享的，为什么？**
两种可能：① 这条 IP 曾经被用于代理业务，历史记录还在；② 检测站把「IP 属性为住宅但连接特征异常」也归入代理判定。看具体判定依据，不要只看结论。

**Q8：换 IP 之后要等多久才能用？**
技术上立刻可用，但建议先静置观察。新 IP 的前几天处于「无历史」状态，部分平台对无历史 IP 更敏感。稳妥做法是先做低风险操作（浏览、停留），几天后再登录重要账号。

**Q9：为什么 ChatGPT / AI 服务特别挑 IP？**
这类服务的风控重点是「防止批量注册与滥用」，对机房 IP 和共享 IP 的拦截最严。实际经验是：机房 IP 基本无法完成付款流程；住宅 IP 里共享人数多的也容易被要求反复验证。

**Q10：有没有必要同时用多个检测站？**
有必要，但不必多。选两家口径不同的（一家侧重多风控源并排，一家侧重泄漏与一致性检查），交叉验证即可。九家全测一遍除了浪费时间没有任何额外信息量。
